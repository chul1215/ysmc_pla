# 변경사항 요약 — 2026.04.21 (4차)

3차 전달분(`20260417_3rd/`) 이후 **공지사항 시스템 전면 재구성** 내역을 정리한 4차 배포본.

## 개요

- **모달 방식 → 독립 상세 페이지 방식**으로 공지사항 열람 구조 변경
- 관리자(`admin.html`) 공지 작성에 **리치 텍스트 에디터(Toast UI Editor)** 및 **첨부파일 업로드** 기능 도입
- 기존 하드코딩된 공지 10건을 **시드 데이터**로 전환하여 localStorage에 자동 주입

## 패키지 구성 (4개 파일)

| 파일 | 상태 | 설명 |
|---|---|---|
| `notice.html` | 수정 | 하드코딩 `<tr>` 제거, localStorage 기반 동적 렌더링, 행 클릭 시 상세 페이지로 이동 |

| `admin.html` | 수정 | 공지 작성 모달에 Toast UI Editor · 첨부파일 업로드 · 작성자 "관리자" 고정 등 추가 |

## 주요 변경 내역

### 1. 공지사항 목록 페이지 (`notice.html`) 개편

- 기존: 하드코딩된 `<tr>` 10개 + 모달 JS
- 변경: `<tbody id="noticesTbody">`만 비워두고 **JS가 localStorage(`ysmc_notices`)를 읽어 동적 렌더링**
- 행 클릭 시: 기존 모달 팝업 → `notice-detail.html?id=<공지ID>`로 **페이지 이동**
- 조회수 컬럼: 고정값(기존 1,284/876/…) → 실제 `views` 필드 반영 (상세 페이지 열람 시 세션당 +1)
- NEW 뱃지: 게시일 기준 7일 이내 공지에 자동 부착 (기존 로직 유지)
- pinned 공지는 최상단 고정, 나머지는 게시일 내림차순

### 2. 공지 상세 페이지 (`notice-detail.html`) 신규 추가

독립된 상세 페이지. URL 예: `/notice-detail.html?id=seed-1`

**레이아웃 구성**
- Breadcrumb: 홈 / 병원소개 / 공지사항 / (제목)
- 상세 카드
  - 배지: [공지(pinned)] · [카테고리] · [NEW(7일 이내)]
  - 제목, 메타 정보 (**작성자 · 게시일 · 수정일 · 조회수**)
  - 본문 HTML (Toast UI Editor에서 생성된 HTML 직접 렌더)
  - 첨부파일 블록 (있을 때만 — 아이콘·파일명·용량·다운로드 버튼)
- 이전글 / 다음글 네비게이션 (목록 정렬 기준, 없으면 disabled 상태)
- 목록으로 / 맨 위로 버튼

**기타 동작**
- 찾을 수 없는 ID 또는 비공개 공지: "공지를 찾을 수 없습니다" 안내 + 목록 복귀 버튼
- 조회수: `sessionStorage('ysmc_notice_viewed_<id>')` 플래그로 탭 세션당 1회만 증가

### 3. 관리자 페이지 (`admin.html`) 공지 작성 업그레이드

- 외부 CDN 추가: Toast UI Editor (`toastui-editor.min.css` / `toastui-editor-all.min.js`)
- 공지 작성 모달 확장: `max-w-lg` → `max-w-3xl`
- 카테고리 선택 제거 → **"공지" 카테고리 고정** (사용자 지시)
- 작성자 **"관리자" 고정** (모달 상단에 표기, 입력 불가)
- 본문 입력: `<textarea>` → **Toast UI Editor(WYSIWYG+마크다운)** 컨테이너
  - 툴바: 헤딩·볼드·이탤릭·스트라이크 / hr·인용 / 순서 리스트·글머리 / 표·이미지·링크 / 코드·코드블록
  - 에디터 영역만 라이트 배경으로 유지(가독성 — 다크 테마인 관리자 페이지 내부에서)
  - **이미지 삽입**: 파일 선택/드래그 시 자동으로 Base64 Data URL로 인코딩 → 본문 HTML 안에 내장
- **첨부파일 업로드 필드 신규**
  - 다중 파일, 허용 확장자: pdf · doc/docx · xls/xlsx · hwp · png/jpg/jpeg/gif/webp
  - Base64로 인코딩되어 `attachments[]`에 저장, 각 파일별 삭제 버튼 제공
  - 권장 총 용량: 5MB 이내 (localStorage 5~10MB 한도 고려)
- 저장 시 자동 관리되는 필드
  - 신규 작성: `date = today, updatedAt = today, views = 0, author = '관리자'`
  - 수정: `date`와 `views` 유지, `updatedAt`만 오늘 날짜로 갱신

### 4. 시드 데이터 (`notice-seed.js`) 신규 추가

기존 `notice.html`에 하드코딩되어 있던 공지 10건을 JS 모듈로 외부화.

- `window.NoticeSeed.seedIfNeeded()` 호출 시 1회만 localStorage에 주입
- `localStorage['ysmc_notices_seeded'] === '1'` 플래그로 중복 주입 방지
- 관리자가 시드 공지를 삭제하면 **복원되지 않음** (사용자의 정상적 운영 의도 존중)
- 관리자가 새로 작성한 공지가 이미 있으면 그대로 유지하고 시드만 append
- 시드 포함 공지: 홈페이지 오픈 / 개인정보처리방침 개정 / 온라인 예약 오픈 / 카카오톡 채널 개설 / 실손보험 서류 / 설날 연휴 / MBC 출연 / 3월 진료시간 변경 / 외상 24시간 접수(pinned) / 신규 개설(pinned) — 총 10건, 각 건 본문은 2~4문단짜리 실제 안내문 수준으로 작성됨

## 데이터 스키마 (`localStorage['ysmc_notices']`)

```js
[
  {
    id: 'seed-1',            // 고유 ID (관리자 생성분은 genId()로 자동)
    category: '공지',         // 고정
    title: '...',
    body: '<p>...</p>',      // Toast UI Editor 산출 HTML (이미지는 Base64 inline)
    author: '관리자',         // 고정
    date: '2025-02-28',      // 게시일 (YYYY-MM-DD)
    updatedAt: '2025-02-28', // 수정일 (YYYY-MM-DD)
    views: 1284,             // 조회수 (상세 페이지에서 자동 증가)
    pinned: true,            // 상단 고정 여부
    visible: true,           // 공개 여부 (false면 목록·상세에 노출 안 됨)
    attachments: [           // 첨부파일 (없으면 빈 배열)
      { name: 'notice.pdf', type: 'application/pdf', size: 123456, data: 'data:application/pdf;base64,...' }
    ]
  },
  // ...
]
```

> **하위 호환**: 기존 admin에서 만든 공지가 `content` 필드만 가지고 있어도 상세 페이지는 `body || content`로 fallback. 새로 저장 시 `content` 필드 자동 제거됨.

## 테스트 시나리오

**A. 공개 사이트 공지 열람 흐름 (신규 방문자)**
1. `/notice.html` 접속 → 시드 10건 자동 주입, pinned 2건 + 일반 8건 표시
2. 임의 행 클릭 → `/notice-detail.html?id=seed-X`로 이동
3. 제목·작성자(관리자)·게시일·조회수 노출 확인 / 본문 HTML 렌더링 확인
4. 이전글·다음글 네비게이션 클릭 시 다른 공지로 이동
5. "목록으로" 버튼 → `/notice.html` 복귀, 조회수 +1 반영 확인 (해당 세션 기준)

**B. 관리자 공지 작성 흐름**
1. `/admin.html` 접속 → 비밀번호 로그인 (`admin1234`)
2. 좌측 사이드바 "공지사항 관리" 선택 → 시드 10건이 목록에 표시됨
3. "새 공지 작성" 클릭 → 모달 오픈, Toast UI Editor 초기화
4. 제목 입력 + 본문에 텍스트·리스트·이미지·링크 삽입 → 이미지는 Base64로 자동 인코딩
5. 첨부파일 1~2개 업로드 (PDF/PNG 등) → 목록에 파일명·용량 표시, × 로 삭제 가능
6. 저장 → 목록 상단에 신규 공지 노출
7. `/notice.html` 새로고침 → 신규 공지 반영 확인 → 행 클릭 → 상세 페이지에서 본문·첨부파일 다운로드 확인

**C. 공지 수정 / 삭제**
1. 목록에서 "수정" → 모달에 기존 제목·본문·첨부파일·옵션 복원
2. 본문 일부 수정 후 저장 → `updatedAt` 갱신, `date`는 원본 유지
3. `/notice-detail.html?id=...`에서 메타에 "수정일" 표기 확인
4. "삭제" → 목록에서 제거, 상세 페이지 직접 URL 접근 시 "공지를 찾을 수 없습니다"

## 퍼블리싱 시 주의

1. **파일 배치**: 4개 파일 모두 웹 루트(기존 `notice.html`이 있던 위치)에 그대로 업로드. `notice-seed.js`는 3개 HTML이 상대 경로(`./notice-seed.js`)로 참조하므로 반드시 같은 디렉터리에 둘 것.
2. **CDN 허용**: 사내 보안 정책상 외부 CDN 차단 환경이면 Toast UI Editor를 번들로 서버에 직접 호스팅하도록 전환 필요 (`admin.html` head의 `<link>` `<script>` 2줄 교체).
3. **localStorage 한도**: Base64 첨부파일이 누적되면 5~10MB 한도에 도달할 수 있음. 대용량 PDF는 가급적 피하고, 필요 시 차후 서버 스토리지 연동 권장.
4. **XSS 노출면**: 본문 HTML은 관리자만 작성하는 것을 전제로 `innerHTML` 렌더링. 비관리자 공개 입력 경로가 추가되면 반드시 sanitize 라이브러리(DOMPurify 등) 도입 필요.
5. **기존 하드코딩 공지와의 중복**: 기존 `notice.html`에 박혀 있던 10건은 이번 배포로 **삭제**되었고, 동일 내용이 `notice-seed.js`의 시드로 재등장함. 실서버에 이전 배포본이 남아있다가 이번 배포를 덮어쓰더라도 데이터 중복은 발생하지 않음 (플래그로 1회 주입).
6. **관리자 비밀번호**: 현재 `admin.html` 내 `ADMIN_PW = 'admin1234'` 상수. 실운영 전 서버 사이드 인증으로 전환 권장 (3차 배포 때부터 명시된 TODO).
